## 1. Problem Statement: The Semantic Gap Between Statecharts and Flat FSMs

In 1987, David Harel introduced **Statecharts** (*"Statecharts: A Visual Formalism for Complex Systems"*), extending conventional finite-state machines (Mealy/Moore automata) with four orthogonal mechanisms to combat visual and specification complexity:

1. **Hierarchy (OR-states / XOR clustering)**: Grouping states into superstates so a single high-level transition replaces $k$ identical outgoing transitions from every child state.
2. **Orthogonality (AND-states / `<parallel>` regions)**: Allowing a system to inhabit multiple independent concurrent sub-machines simultaneously without manually specifying the Cartesian product of their states.
3. **History (`<history type="shallow|deep">`)**: Remembering the last active sub-configuration of a composite state upon exit and restoring it dynamically upon re-entry.
4. **Extended Data Variables & Guard Conditions (`<datamodel>`, `cond="..."`)**: Conditioning transitions on internal variables and cross-region state predicates (`In('State')`).

While Harel Statecharts (standardized by the W3C as **SCXML — State Chart XML**) are ideal for human modeling in tools like **itemis CREATE (formerly YAKINDU Statechart Tools)**, downstream automated analysis and learning algorithms typically require **explicit, flat Finite-State Machines**:

$$M_{\text{flat}} = (Q, \Sigma, \Gamma, \delta, \lambda, q_0)$$

where:
- $Q$ is a finite, flat set of discrete states,
- $\Sigma$ is a finite alphabet of discrete input events,
- $\Gamma$ is a finite set of entry/exit/transition output actions,
- $\delta: Q \times \Sigma \to Q$ is a total or partial deterministic transition function,
- $\lambda: Q \times \Sigma \to \Gamma^*$ is the action output function, and
- $q_0 \in Q$ is the unique initial state.

> [!IMPORTANT] Primary Downstream Use Case: Tabular Reinforcement Learning (Q-Learning)
> This project was specifically engineered to feed flattened SCXML models into **Tabular Q-Learning / RL agents** and **FSM-based automated test/verification pipelines**. A Q-learning agent maintains a table $Q(s, a)$ over discrete state identifiers $s \in Q$ and discrete actions/events $a \in \Sigma$.
>
> For a Q-learning agent to explore a statechart without an embedded SCXML interpreter:
> 1. **Every reachable system configuration** (active leaf states across all parallel regions + guard-relevant variable valuations + active history memories) must be encoded as a distinct, self-contained state ID $s \in Q$.
> 2. **Every transition target** must exist as a top-level key in the JSON dictionary (**0 broken targets**).
> 3. **Every transition input** must be a non-null string event (**0 `null` events**; automatic/eventless transitions are normalized to `"_auto"`).
> 4. **Every `(state, input)` pair** must resolve deterministically or carry explicit disambiguating labels (**0 ambiguous non-deterministic transitions**).

## 2. High-Level Input / Output Contract

The compiler ([lib/scxml_flattener_full.exs](file:////wsl.localhost/Ubuntu-24.04/home/jvrmalv/code/statechart_flattener/lib/scxml_flattener_full.exs)) accepts any W3C SCXML file (`.scxml`) and produces two synchronized artifacts:

### 2.1 Flat JSON Representation (`*_flattened.json`)
Designed for direct consumption by Python/Elixir Reinforcement Learning environments and automated verifiers ([harel_watch/verify_flattened.py](file:////wsl.localhost/Ubuntu-24.04/home/jvrmalv/code/statechart_flattener/harel_watch/verify_flattened.py)):

```json
{
  "initial_state": "main_Off__",
  "states": {
    "main_Off__": {
      "onentry": ["turn_light_off()"],
      "onexit": [],
      "transitions": [
        {
          "input": "switch",
          "target": "main_On__",
          "actions": []
        }
      ]
    },
    "main_On__": {
      "onentry": ["turn_light_on()"],
      "onexit": [],
      "transitions": [
        {
          "input": "switch",
          "target": "main_Off__",
          "actions": []
        }
      ]
    }
  }
}
```

### 2.2 Flat W3C SCXML Representation (`*_flattened.scxml`)
A single-level `<scxml>` document containing only atomic `<state>` elements (no nested `<state>`, no `<parallel>`, no `<history>`, no `<datamodel>`), where all hierarchy, concurrency, variable state, and history memory have been compiled into the state names and transition targets:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<scxml xmlns="http://www.w3.org/2005/07/scxml" version="1.0" initial="main_Off__">
  <state id="main_Off__">
    <onentry><log expr="turn_light_off()"/></onentry>
    <transition event="switch" target="main_On__"/>
  </state>
  <state id="main_On__">
    <onentry><log expr="turn_light_on()"/></onentry>
    <transition event="switch" target="main_Off__"/>
  </state>
</scxml>
```

## 3. Core Engineering Challenges Solved

Transforming full-featured SCXML into a flat FSM exposes five classic theoretical challenges in formal methods, each addressed by a dedicated subsystem in `statechart_flattener`:

| Challenge | Naïve Flattening Failure Mode | `statechart_flattener` Solution | Detailed Note |
| :--- | :--- | :--- | :--- |
| **1. Name Collisions Across Regions** | Sibling states named `On`, `Off`, `entry_0`, or `Zero` overwrite each other when hierarchy is stripped. | Full lexical path prefixing (`parent_child_leaf`) + LCA-based relative scope resolution + global unique-suffix fallback. | [[1.3 - Lexical Normalization & Scope Resolution]] |
| **2. Nested Orthogonal Regions (`<parallel>`)** | Multi-level `<parallel>` inside `<parallel>` (e.g., `watch.scxml` `_root` $\supset$ `Operation`) breaks single-level region interleaving. | Bottom-up recursive parallel flattening (`find_parallel_states_bottom_up/1`) + active region-component replacement + cross-region `In(...)` resolution. | [[1.4 - Orthogonal Regions & Parallel Composition]] |
| **3. Data Space Explosion ($|D_1 \times \dots \times D_k|$)** | Expanding 14 variables in `watch.scxml` creates $2^{14} \times 64 = 1,048,576+$ base states and hangs compilation. | Static dependency partitioning into **guard-relevant** vs. **display-only** variables + **nearest-value domain snapping (`snap_to_domain/2`)**. | [[1.5 - DataModel & Combinatorial Explosion Mitigation]] |
| **4. Dynamic History Memory (`<history>`)** | Static history replacement always jumps to the initial default substate, forgetting which substate was actually active before exit. | **Product-Automaton Synthesis** ($Q \subseteq S_{\text{atomic}} \times D_{\text{vars}} \times H_{\text{memory}}$) tracking live history maps `hist_env` during BFS reachability. | [[1.6 - Generalized History Synthesis (Product Automaton)]] |
| **5. Synthetic Non-Determinism** | Inheriting transitions from ancestors or unresolved runtime guards produces duplicate `(state, event)` transitions (4,480 ND states in `watch.scxml`). | W3C inner-first + document-order shadowing (`dedup_by_event_priority/1`) + dynamic guard preservation (`"event [cond]"`). | [[1.7 - Transition Priority, Shadowing & Determinism]] |
